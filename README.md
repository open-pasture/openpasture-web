# openpasture website

The closed repository for [openpasture.dev](https://openpasture.dev). The agent
kit is a separate public repository,
[open-pasture/openpasture-agent-kit](https://github.com/open-pasture/openpasture-agent-kit).

## What it is

A small static site with one server. `build.js` composes `layouts/base.html`
with the page fragments in `pages/` and the partials in `partials/`, copies
`assets/`, writes `robots.txt` and `sitemap.xml` from the page list, and puts
all of it in `dist/`. `server.js` (Express) serves `dist/`, applies the
`REDIRECTS` map for routes from earlier versions of the site, and handles
`POST /api/contact` through Resend.

Eleven pages: index, project, collar, notes, about, involved, docs, pricing,
privacy, terms, and 404. One stylesheet, `assets/op.css`. One script,
`assets/site.js`. Self-hosted Barlow 400 and 500 and IBM Plex Mono 400 in
`assets/fonts/`. The figures are inline SVG partials.

## Run locally

Requires Node 20.6 or newer.

```
npm ci
npm start
```

`npm start` runs the build first (`prestart`), then serves on
http://localhost:3000. `npm run build` alone writes `dist/`. Without
`RESEND_API_KEY` the contact endpoint logs submissions to the console instead
of sending mail.

To exercise the real mail path locally, copy `.env.example` to `.env`, fill it
in, and run `npm run dev`, which builds and then starts the server with `.env`
loaded. `.env` is gitignored.

## Environment

`server.js` reads these and nothing else. `.env.example` is the same list with
comments, and doubles as the checklist for the Railway service's variables.

| Variable | Purpose |
| --- | --- |
| `RESEND_API_KEY` | Resend API key for the contact endpoint. Unset: submissions are logged locally, and the form answers 503 in production. |
| `CONTACT_EMAIL` | Inbox that receives contact submissions. Required whenever `RESEND_API_KEY` is set; the server exits at start if it is missing. |
| `RESEND_FROM` | Sender address on a domain verified in Resend, for example `openpasture <hello@yourdomain>`. Optional: unset, the server sends as Resend's test sender, which only delivers to the Resend account owner. |
| `PORT` | Port for the Express server. Railway injects it; locally it defaults to 3000. |
| `NODE_ENV` | Set to `production` on Railway. Leave unset locally. |
| `RAILWAY_ENVIRONMENT` | Injected by Railway, never set by hand. Its presence makes the server treat the run as production. |

## Deploy

Railway auto-deploys `main` to openpasture.dev. Railway builds with
`npm run build` and starts with `npm start`, its Node defaults; the repo sets
no custom commands. `npm start` rebuilds through `prestart`, so the served
`dist/` always matches the commit. Environment variables are set on the
Railway service; set `NODE_ENV=production` there. There is no config-as-code
file for the deployment in this repo, so the service's own settings cannot be
read from here; see the unresolved-inputs table in
[docs/repositioning/README.md](docs/repositioning/README.md).

Caching: everything under `/assets` is served for a year as immutable. The
stylesheet, script, icons, and share image are linked with `?v=`, a hash
`build.js` computes over everything in `assets/`, so a change to any of them
shows up on the next deploy. The font files are the exception: `op.css` and
the preload links reference them without a version, so a changed font needs a
new filename (the names already carry the weight). HTML, `robots.txt`, and
`sitemap.xml` are served with `no-cache`. Unknown routes return the 404 page
with status 404.

## Editing

- Author pages as fragments in `pages/`, each starting with a
  `<!--meta title/description/nav -->` comment.
- `{{key}}` tokens resolve from the page's meta comment (`title`,
  `description`, `nav`), the computed `canonical`, or `SITE` in `build.js`
  (URLs, contact address, status date, share-image alt text). `{{> name}}`
  inlines `partials/name.html`. The build fails on an unresolved token or a
  missing partial.
- `server.js` sends a strict Content-Security-Policy (`style-src 'self'`,
  `script-src 'self'`, `img-src 'self' data:`). No style attributes, `<style>`
  blocks, or inline scripts in pages or partials; styling goes in `op.css`,
  behavior in `site.js`.
- Never edit `dist/`. It is generated and gitignored.
- Present-tense progress claims are dated: the status list in
  `partials/status.html`, dated by `SITE.statusDate` and `SITE.statusDateIso`
  in `build.js`, and the dated entries on `/notes`. Copy elsewhere may restate
  them only in the same terms; revisit it when the status list changes.
- Redirects live in `REDIRECTS` in `server.js`.
- `robots.txt` and `sitemap.xml` are generated by `build.js` from the pages in
  `pages/`, minus the 404 page. Adding or removing a page updates both.
- The share image `assets/og.png` (1200 by 630) and the icon PNGs
  (`favicon-32.png`, `favicon-16.png`, `apple-touch-icon.png`) are written by
  `npm run render-images`, which drives the installed Google Chrome headless
  so the site's own fonts are used. macOS only as written: it crops with
  `sips` and expects Chrome at its default path; set `CHROME=/path/to/chrome`
  to override. `og.png` is rendered from
  `scripts/og-source.svg`; the three icon PNGs are drawn from the pixel
  pattern hard-coded in the script. The mark's pattern lives in four places
  that must be kept identical: `assets/favicon.svg`, `partials/mark.html`,
  `scripts/og-source.svg`, and the rows array in `scripts/render-images.js`.
  Edit those sources and rerun the script rather than editing the PNGs. Their
  URLs carry the `?v=` hash, so a re-render shows up on the next deploy
  without renaming anything.
- The drawings take every color from the `k-` classes in `assets/op.css`,
  each bound to a palette token, and `scripts/og-source.svg` paints with
  `var()`, which resolves because the render script inlines it with the
  `:root` block. Do not put hex literals in the SVG. The three exceptions,
  because none can read a stylesheet, are `assets/favicon.svg`, the
  `theme-color` meta in `layouts/base.html`, and the pixel-grid data URI on
  `.hero .px` in `op.css`; each carries a comment naming the token it
  mirrors.
