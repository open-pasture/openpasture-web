Repositories

What is public, and what is not

Public openpasture-agent-kit — AGPL-3.0 The whole decision layer. Domain objects, tools, skills, knowledge base, storage backends, ingestion pipelines, the CLI, and the connectors. This is the part that has to stay open for the argument to mean anything.
Private openpasture-cloud The hosted control plane: accounts, billing, tenant key management, and the monitoring portal. Operational plumbing around the kit. It contains no farming logic that the kit does not already have.

The business model

Revenue from hosting, not rent on access

We charge for the parts that are genuinely hard to run — imagery pipelines, model hosting, sync, managed infrastructure — the way open-core infrastructure companies have built durable businesses for two decades. A farm that self-hosts everything pays us nothing and loses nothing.

The design goal is that if our hosted service disappeared tomorrow, every farm keeps its data and the software keeps running on a machine in the farmhouse. AGPL is how we make that binding on ourselves as much as on anyone else: nobody, including us, gets to enclose an improved version behind an API.

Self-hosting

Running the whole thing yourself

Default storage is SQLite on local disk, so the minimum viable deployment is a Python install on one machine. Convex is available if you want sync across devices, and you can point it at your own deployment rather than ours.

local, no accounts, no network dependency
pip install -e .

export OPENPASTURE_STORE=sqlite
export OPENPASTURE_DATA_DIR="$HOME/.openpasture"

openpasture tool run generate_morning_brief --json '{}'
